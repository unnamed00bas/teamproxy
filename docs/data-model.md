# Data model

All tables use string UUID primary keys and `created_at` / `updated_at`
timestamps (except append-only `health_checks`). Tags are stored as JSON arrays
on the owning entity for MVP simplicity (a normalized tag table is a post-MVP
item — see roadmap).

## Entities

### users
Admin accounts. `role ∈ {superadmin, operator, viewer}`, `is_active`,
`hashed_password` (bcrypt).

### sites
A physical/logical location. `slug` (unique), `name`, `status`,
`wg_tunnel_subnet`, `local_subnets[]`, `tags[]`, `gateway_peer_id` (soft ref),
`agent_version`, `last_seen`.

### peers
WireGuard peers. `site_id`, `name`, `public_key`, `private_key_ref` (vault
reference, **not** the key), `assigned_tunnel_ip`, `allowed_ips[]`, `endpoint`,
`role ∈ {site_gateway, admin}`, `status`, `enabled`, handshake/transfer stats.

### nodes
Hosts inside a site. `site_id`, `hostname`, `private_ip`, `platform`,
`is_gateway`, `status`.

### services
Internal service registry. `site_id`, `node_id`, `name`, `slug`,
`protocol_type ∈ {http, https, tcp, udp}`, `backend_host`, `backend_port`,
`backend_scheme`, `healthcheck_path/expected_code`, `owner`, `enabled`,
`exposure_mode ∈ {public, private, disabled}`.

### publications
A routing rule exposing a service. `service_id`, `entrypoint_type ∈ {web, tcp,
udp}`, `domain_or_sni`, `path_prefix`, `tls_enabled`, `tls_mode`,
`published_port`, `public_enabled`, `maintenance_mode`, `priority`,
`middleware_profile`.

### domains
DNS registry. `fqdn` (unique), `record_type`, `active`, `publication_id`.

### certificates
TLS certificate tracking. `domains[]`, `status ∈ {ok, pending, error}`,
`issuer`, `not_before`, `not_after`, `last_error`.

### deploy_revisions
`number`, `commit_sha`, `initiated_by`, `mode ∈ {auto, manual}`, `status`,
`summary`, `health_result`, `rollback_available`.

### audit_events
`actor_id/email`, `action`, `target_type/id`, `before` (JSON), `after` (JSON),
`result`, `deploy_revision_id`.

### health_checks
Append-only. `target_type`, `target_id`, `status ∈ {green, yellow, red}`,
`detail`, `checked_at`.

### generated_configs
Rendered config revisions. `revision`, `kind`, `content`, `checksum` (sha256),
`applied`, `applied_at`, `apply_error`.

### secrets_metadata
Metadata only — `name`, `description`, `kind`, `last_rotated_at`. Never values.

## Relationships

```
site 1───* peer
site 1───* node
site 1───* service
node 1───* service
service 1───* publication
publication 1───* domain
```

## Migrations

Alembic is configured for async engines (`alembic/env.py`). The baseline
migration was autogenerated from the models. Workflow:

```bash
alembic revision --autogenerate -m "change"
alembic upgrade head     # also run automatically by the backend entrypoint
```
